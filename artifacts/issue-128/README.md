# Проверка экрана загрузок (#128, #94)

Эмулятор `nextgallery-api36-dev`, Android 16, приложение debug, сервер `http://test.syrok/`, тестовая учётная запись. Использованы только одноразовые копии `ng152-*`. После проверки они удалены с устройства, с сервера и из корзины; fixtures не изменялись. Проверка 7 ноября 2026, после переделки экрана по варианту 2 прототипа ([gist](https://gist.github.com/syrok0010/aca3971069294bbe007779417df3fe1b)).

Экран группирует файлы по состоянию: «Загружается», «В очереди», «Готово». Партии не показываются. У каждого файла виден размер, у групп — количество файлов и их общий размер.

- [outcomes.png](outcomes.png): все три группы сразу. Текущий файл с переданным объёмом, очередь с «Отменить все», готовые файлы: ошибка в начале группы, затем «Загружен» и отменённый.
- [cancel-all.png](cancel-all.png): «Отменить все» останавливает текущий PUT и снимает очередь. Ранее завершённые файлы остаются в истории.
- [cancellation.mp4](cancellation.mp4): весь сценарий одной записью `agent-device`: загрузка, отмена файла из очереди, «Отменить все», затем переход из итогового уведомления. Запись перекодирована (540 px, без звука), сценарий не менялся.
- [notification.png](notification.png), [from-notification.png](from-notification.png): итоговое уведомление и экран, который открывается нажатием на него.

Как получены состояния. Зависший PUT и ошибка получены приостановкой стенда (`docker compose pause app`). Файл, PUT которого упал по таймауту, оказался на сервере: ошибка не откатывает байты, уже принятые сервером. Сырое сообщение `timeout` в тексте ошибки было и до этого PR, оно вынесено в #172. «Уже в облаке» и конфликт имени в этом прогоне не воспроизводились: дубликат с теми же байтами склеился с облачной копией по identity и в загрузку не попал. Оба исхода покрыты JVM-тестами размещения файла.

JVM: 305 тестов, 0 failures/errors/skipped. Прошли `spotlessCheck`, `verifyFeatureBoundaries`, `assembleDebug`, `:app:compileAutomationAndroidTestKotlin`, `:core:media:test`. Gradle запускался с двумя workers и heap 2 ГБ. Instrumentation только скомпилированы, полного connected-прогона не было. Отмена с добавлением в альбом проверена JVM-контрактом follow-up; живой альбом в UI не создавался.

Очередь не переживает process death. Отмена не откатывает байты, уже принятые сервером до закрытия соединения.
