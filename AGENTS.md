# Инструкции для агентов

- Пиши рабочую проектную документацию на русском, если пользователь не попросит иначе.
- Важные архитектурные решения не подавай как вкусовщину или "best practice" без объяснения.
- Для ADR фиксируй контекст, критерии выбора, альтернативы, последствия и открытые вопросы.
- Документируй важное, но не все подряд: записывай решения, проверенные факты, риски, ограничения и договоренности, которые повлияют на будущий код или архитектуру.
- Не раздувай документы оперативными заметками, очевидными шагами, временными мыслями и деталями, которые легко восстановить из кода.
- Если информация полезна только на время текущей задачи, оставь ее в сообщении пользователю, а не в docs.
- Не делай коммиты без прямой просьбы пользователя.
- Не трогай unrelated-код и настройки без необходимости.

## Продуктовые инварианты

Эти факты легко теряются из контекста, а от них зависят решения в коде и тестах.

- **Приложение только однопользовательское.** Выход удаляет все данные приложения, после него приложение в состоянии свежей установки (#53). Исходи из того, что аккаунт смениться не может: не привязывай данные к аккаунту, не пиши защиту и тесты на «данные прежнего аккаунта».
- **Ранний этап, пользователей нет.** Совместимость данных, API и поведения не нужна. Breaking change приветствуется, если упрощает код или убирает технический долг; миграции и backfill не пиши.

Подробнее — `docs/product/vision.md`.

## Agent skills

### Issue tracker

Задачи ведутся в GitHub Issues этого репозитория через `gh` CLI. См. `docs/agents/issue-tracker.md`.

### Triage labels

Используется минимальный набор labels: существующие GitHub labels плюс `ready-for-agent` и `needs-decision`. См. `docs/agents/triage-labels.md`.

### Domain docs

Проект single-context: продуктовые документы в `docs/product/`, исследования в `docs/research/`, решения в `docs/adr/`. См. `docs/agents/domain.md`.

### Android-разработка

При изменении Android-кода, UI или тестов следуй правилам выбора устройства в `docs/agents/android-development.md`.

### Тесты

Для JVM-тестов и instrumentation используй `docs/agents/testing.md`.

### Тестовый Nextcloud

Для интеграционных проверок Nextcloud/Memories, тестовых медиа, скриншотов для PR и управления стендом читай `docs/agents/test-nextcloud.md`.

### Релизная сборка

Подпись, сборка release и версии — в `docs/agents/release.md`.
