# Android-разработка для агента

Выберите среду и назовите устройство проверки:

- На headless-машине `syrok-server` используйте локальный SDK и AVD. Подготовка,
  обслуживание и команды описаны в `dev/android/README.md`.
- На ноутбуке с HITL используйте локальный toolchain и личный телефон по
  `docs/agents/testing.md`.

## Цикл на syrok-server

1. Проверьте `git status --short`, прочитайте затрагиваемый код и ближайшие тесты.
2. Запустите минимальную подходящую Gradle-задачу локально. Для JVM-тестов —
   `./gradlew --no-daemon --max-workers=2 :app:testAutomationUnitTest`, для APK —
   `:app:assembleAutomation`.
3. Для интерактивной проверки используйте `nextgallery-api36-dev` через T3 Code.
   При доступных инструментах устройства используйте `device_*` и `agent-device`;
   для обычного терминала команды приведены в `dev/android/README.md`.
4. Сохраните доказательства в `build/android-dev/`: screenshot и при необходимости
   UI hierarchy для UI; logcat для падений; наблюдаемое состояние для данных.
5. После изменения Android runtime выключите dev-AVD и выполните
   чистый прогон на `nextgallery-api36-smoke` по `dev/android/README.md`.
   Он проверяет запуск приложения и instrumentation на отдельном userdata. Успех требует отсутствия
   неожиданного ANR. При нехватке памяти не запускайте два AVD одновременно.
6. В результате укажите выполненные Gradle-задачи, runtime-сценарий, артефакты
   и непроведённые проверки. Выполните `git diff --check`.

`nextgallery-api36-dev` сохраняет данные; сброс допускается только для отдельного
`nextgallery-api36-smoke`. На физическом телефоне используйте automation-вариант,
чтобы сохранить данные debug-приложения. Эмулятор не заменяет проверку поведения,
зависящего от реального железа или OEM.

ADB остаётся локальным. Удалённый экран передаётся через защищённое соединение T3.
