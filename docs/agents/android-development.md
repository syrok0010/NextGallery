# Android-разработка для агента

## Выбор устройства

По умолчанию используйте `nextgallery-api36-dev` на `syrok-server` через T3 Code.
На `syrok-server` выбирайте локальный device host; на `syrok-arch` — SSH device
host `syrok-server` через T3 Code Device Hub. Машина агента не меняет выбор
устройства: подключённый телефон сам по себе не разрешает использовать его.

Реальный телефон используйте только по явному указанию пользователя. До
установки APK или тестов определите согласованный ADB serial; если телефон
неоднозначен, уточните его. Правила тестов — в `testing.md`.

## Работа через T3 Code

1. Вызовите `device_list`, выберите host и `nextgallery-api36-dev`, затем
   `device_open`. Используйте возвращённую команду `agent-device` и её target
   arguments для управления именно этим устройством. В панели Device человек
   может наблюдать экран и взаимодействовать с приложением.
2. Установите automation APK и воспроизведите изменённый сценарий. Используйте
   `agent-device` для установки, ввода и диагностики; синтаксис берите из
   подсказки `device_open` и справки CLI. Скриншоты доступны через
   `device_screenshot`.
3. После работы выключите запущенное вами устройство через `device_close` с
   `shutdown=true`, если пользователь не попросил оставить его работающим.
   Закрытие вкладки само по себе не выключает эмулятор. Не выключайте устройство,
   занятое чужой проверкой.

Android-видео в браузере требует HTTPS или localhost. Для серверного интерфейса
используйте `https://t3.syrok/`. Если device host или инструменты недоступны,
сообщите об этом; переход на телефон требует явного указания пользователя.

Device Hub передаёт экран и управление, но не делает удалённый AVD локальным
ADB-устройством. На `syrok-arch` передавайте APK на `syrok-server` для команды,
которая читает файл на удалённом хосте. Instrumentation запускайте на машине,
чей ADB видит выбранный эмулятор, из checkout той же проверяемой ревизии.
Не публикуйте ADB в сеть ради доступа через Device Hub.

## Цикл проверки

1. Проверьте `git status --short`, прочитайте затрагиваемый код и ближайшие тесты.
2. Выполните минимальные подходящие Gradle-задачи по `testing.md`. Собирайте APK
   до запуска эмулятора, чтобы снизить пиковое потребление памяти.
3. Проверьте поведение на dev-AVD через T3 Code. Сохраните доказательства в
   `build/android-dev/`: screenshot и при необходимости UI hierarchy для UI,
   logcat для падений, наблюдаемое состояние для данных.
4. Для финальной runtime-проверки используйте отдельный `nextgallery-api36-smoke`
   на том же device host, установите проверяемый APK и выполните instrumentation
   по `testing.md`. Воспроизведите изменённый сценарий и проверьте отсутствие
   ANR и падений. Артефакты сохраните в `build/android-smoke/`. Не считайте запуск
   через T3 автоматическим сбросом userdata: для сценария с чистым состоянием
   подготовьте его отдельно только на smoke-AVD. Dev сохраняет рабочие данные.
5. Выполните `git diff --check`. В результате укажите host и устройство,
   Gradle-задачи, runtime-сценарий, артефакты и непроведённые проверки.

На `syrok-server` используйте один AVD за раз. Если для проверки нужен реальный
сенсор или OEM-поведение, укажите ограничение эмулятора и запросите явный выбор
телефона вместо автоматического переключения.
