# Форматирование Kotlin

Единый форматтер — Spotless с ktlint; версии закреплены в Gradle, стиль — в корневом `.editorconfig`. Настройки EditorConfig также читает Android Studio. При расхождениях результат `spotlessApply` считается окончательным.

```bash
./gradlew spotlessApply  # Отформатировать Kotlin и Gradle Kotlin DSL
./gradlew spotlessCheck  # Проверить без изменения файлов
```

Проверка также включена в задачи `check` модулей и отдельный GitHub Actions workflow для PR и `main`. Форматируются исходники и тесты всего проекта; generated/build и временные прототипы исключены.

Используем встроенный стиль ktlint `android_studio`, без собственных порогов числа параметров или длины цепочек. Он сохраняет привычные присваивания `val value = call(...)` без обязательного переноса после `=`. Переносы и отступы определяет выбранный стиль. Для многострочных объявлений и вызовов дополнительно включены висящие запятые (trailing comma).

Исключения касаются проверок, а не раскладки: разрешены имена Composable-функций, отключены требования переименовать файлы/свойства и запрет wildcard-imports. Правило `max-line-length` ktlint остаётся включённым: от него зависят автоматические переносы, включая тело функции после `=`. Используется лимит встроенного стиля (100 символов). Spotless подавляет только оставшиеся сообщения `standard:max-line-length`, которые форматтер не смог исправить, например для длинных строковых данных и имён тестов. Это подавление находится в `build.gradle.kts`, а не в `.editorconfig`, и не отключает автоматическое форматирование длинного кода.

Уточнения для выражений и цепочек:
- `binary-expression-wrapping` отключено: в ktlint 1.8 оно может разорвать короткое сравнение из-за длины окружающей строки.
- `expression-operand-wrapping` включено отдельно (экспериментальное правило ktlint): в многострочных логических выражениях перенос идёт после `&&`/`||`, сравнения остаются целыми. Правило нормализует существующие переносы, но не разбивает автоматически каждое длинное однострочное условие.
- `chain-method-continuation` включено без порога числа операций: цепочка либо помещается в строку, либо её вызовы располагаются по одному на строку. Ограничение ktlint 1.8: после многострочного списка аргументов следующий вызов может приклеиваться к закрывающей `)`. Короткие списки аргументов лучше оставлять в строке.
- `function_signature_body_expression_wrapping = multiline` отделяет многострочное тело функции от сигнатуры после `=`; это не требует такого же переноса для каждого `val`.
