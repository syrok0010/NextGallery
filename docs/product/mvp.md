# MVP

## Направление MVP-1

Первый MVP: remote-first клиент для Memories/Nextcloud.

Минимальный полезный сценарий:

1. Пользователь указывает адрес своего Nextcloud.
2. Приложение проходит Nextcloud Login Flow v2 и получает app password.
3. Приложение проверяет доступность Memories API.
4. Приложение загружает удаленный timeline.
5. Пользователь видит сетку фото/видео.
6. Пользователь открывает элемент и видит preview/original-версию.
7. Приложение кеширует базовые метаданные и thumbnails.

## Почему не sync-first

Синхронизация - один из самых сложных блоков продукта:

- фоновые ограничения Android;
- конфликты между локальным и удаленным состоянием;
- дубли;
- удаление и восстановление;
- сетевые ошибки;
- квоты и ограничения сервера;
- энергопотребление.

Если начать с полной синхронизации, легко потратить много времени до появления видимого результата. Remote-first MVP быстрее проверяет главный риск: можно ли построить приятный native UX поверх Memories/Nextcloud.

## Почему не local-first

Локальная галерея через Android MediaStore важна, но она не проверяет уникальную ценность проекта. Хороших локальных галерей уже много. Отличие NextGallery - интеграция с личным Nextcloud/Memories архивом.

## Обязательные возможности MVP-1

- Подключение аккаунта через Nextcloud Login Flow v2.
- Сохранение учетных данных безопасным способом.
- Проверка `/apps/memories/api/describe`.
- Загрузка списка дней через Memories `/apps/memories/api/days`.
- Загрузка фото конкретного дня через `/apps/memories/api/days/{id}`.
- Отображение timeline/grid в Compose.
- Загрузка thumbnails через Memories image preview API.
- Экран detail для одного `MediaItem`.
- Базовый локальный кеш метаданных.
- Обработка пустого состояния, ошибки авторизации и недоступности Memories.

## Не цели MVP-1

- Автоматическая загрузка локальных фото на сервер.
- Двусторонняя синхронизация.
- Редактирование EXIF.
- Создание альбомов.
- Удаление файлов.
- Шаринг.
- People/places/tags.
- Video transcoding UX.
- Поддержка нескольких аккаунтов.

## Текущее dev-допущение

До отдельного решения автора приложение считается личным dev-приложением, установленным только на одном устройстве автора. Пользователей, которым нужна совместимость локального состояния между версиями, пока нет.

Практическое следствие: для MVP-1 не проектируем миграции, backward compatibility локальных storage/schema форматов, восстановление старых dev-сессий и cleanup несовместимых состояний. Ломающие изменения допустимы, а переустановка приложения считается нормальным способом сбросить локальное состояние.

Когда это перестанет быть актуально, автор сообщит отдельно. После этого нужно будет пересмотреть storage/cache/schema decisions и добавить явные migration/compatibility требования.

## MVP-2: локальные фото

После remote-first вертикали добавить `LocalMediaSource` поверх Android MediaStore:

- запрос полного runtime-доступа к локальным изображениям и видео;
- чтение локальных фото и видео;
- единая доменная модель с remote media;
- признак "есть локальная копия" / "есть remote-копия";
- первый вариант unified timeline.

Unified timeline остается за существующей авторизацией Nextcloud. Локальные фото не образуют отдельный доступный без аккаунта режим: после первого успешного Login Flow сохраненная сессия открывает общий timeline при последующих запусках без повторного входа.

Первый срез не поддерживает Android Selected Photos Access как рабочий режим timeline. На Android 14+ системный диалог все равно позволяет выбрать partial access, поэтому приложение должно распознать это состояние, не выдавать выбранную подвыборку за полную локальную библиотеку и предложить выдать полный доступ. Полноценная поддержка partial access планируется отдельной задачей.

После выдачи полного доступа LocalMediaSource читает все доступные изображения и видео из MediaStore. Отдельный выбор папок/buckets, как в Memories Android, в первый срез не входит.

Если пользователь пропустил или отклонил доступ, cloud timeline продолжает работать. Приложение не повторяет системный permission dialog автоматически при следующих запусках: явное действие «Показать фото с устройства» снова объясняет запрос и запускает permission flow. При окончательном запрете действие ведет в настройки приложения; при partial access объясняется, что первый срез требует полного доступа.

Cached MediaStore index не считается доказательством текущего доступа. При утрате full permission локальные копии исключаются из рабочей timeline projection; объединенные объекты остаются как cloud-only. После восстановления полного доступа выполняется полная сверка MediaStore и локальные копии возвращаются к сохраненным `MediaId`.

LocalMediaSource наблюдает за изменениями MediaStore через `ContentObserver`, объединяя серии событий перед пересборкой timeline. При возвращении приложения в foreground выполняется полная сверка MediaStore, потому что изменения могли произойти при неработающем процессе. Добавление и удаление локальных элементов соблюдают scroll anchor и инварианты текущей viewer surface.

Для положения local-only объекта в timeline используется первая валидная дата из `DATE_TAKEN`, `DATE_MODIFIED`, `DATE_ADDED`. Fallback даты влияют на сортировку, но не подменяют `epoch`, используемый в совместимом с Memories вычислении `AUID`.

Локальный индекс хранится в Room как быстро показываемая проекция, а MediaStore остается источником истины. При повторном запуске cached local projection отображается сразу и сверяется в фоне; при первом индексировании результаты публикуются порциями от новых к старым с ненавязчивым статусом прогресса. Полное сканирование MediaStore не блокирует первый показ timeline.

### Признак облачной копии

Каждый тайл медиаобъекта с облачной копией показывает иконку облака в правом верхнем углу — как для cloud-only, так и для объединенного local+cloud объекта. У local-only объекта иконки нет.

Иконка остается видимой на placeholder, если metadata облачного объекта известны, а thumbnail отсутствует. Для читаемости на светлом изображении используется компактный полупрозрачный темный фон или тень. Video badge/длительность располагается справа снизу и не пересекается с облачным индикатором.

Облачная иконка не является отдельным интерактивным элементом и не получает собственный TalkBack focus. Наличие облачной копии добавляется в semantics/content description самого тайла; полноценный accessibility-аудит остается отдельной работой.

### Инкрементальная сборка unified timeline

После авторизации первый срез не ждет одновременной готовности local и remote источников. Сначала показываются доступные локальные объекты и cached cloud metadata, параллельно выполняется refresh Memories, затем публикуется пересобранная объединенная проекция с дедупликацией.

После refresh тайл может получить облачный индикатор, объединиться с remote-копией или переместиться по канонической дате Memories. Это принято как проверяемая гипотеза первого среза; если перестройки окажутся визуально мешающими, политика публикации обновлений должна быть пересмотрена отдельно.

При каждой пересборке unified timeline сохраняется scroll anchor: первый видимый медиаобъект и его смещение от верхней границы viewport. Если объект объединился с другой копией, anchor следует за объединенным identity; если исчез — выбирается ближайший доступный объект по времени. Добавление, удаление и дедупликация элементов выше viewport не должны заметно сдвигать текущее место пользователя.

Открытый viewer получает обновленный порядок unified timeline без замораживания всей `viewer sequence`: предыдущая и следующая страницы могут измениться после refresh. Текущий медиаобъект при этом закреплен по identity и не должен мигать, заменяться другим объектом или пересоздавать уже показанную viewer surface.

Если текущий медиаобъект исчез из обновленного timeline, viewer временно удерживает его как текущую страницу. После перехода на соседнюю страницу или закрытия viewer исчезнувший объект удаляется из sequence; его исчезновение не должно само по себе заменить открытую поверхность другим фото.

## MVP-3: синхронизация

После появления remote и local источников можно проектировать sync engine:

- upload queue;
- download/offline queue;
- background work через WorkManager;
- политика конфликтов;
- retry/backoff;
- пользовательские состояния "только Wi-Fi", "только зарядка", "не синхронизировать эту папку".
