# Видение проекта

## Рабочее название

NextGallery.

## Идея

NextGallery - native Android-клиент для просмотра и дальнейшей синхронизации фото и видео между Android-устройством и Nextcloud/Memories.

Проект начинается как личный учебный и продуктовый эксперимент, но должен быть устроен так, чтобы позже его можно было развивать как open-source проект.

## Для кого

- Пользователь Nextcloud, который хранит личный фотоархив на своем сервере.
- Пользователь Memories, которому нужен качественный native Android-клиент.
- Разработчик, которому интересно современное Android-приложение на Kotlin и Compose.

## Проблема

У Nextcloud/Memories есть сильная серверная часть для фотоархива, но хочется Android-клиент, который ощущается как настоящая системная галерея:

- быстрый timeline;
- удобный просмотр удаленных фото;
- постепенная поддержка локальных фото;
- понятное состояние кеша и синхронизации;
- хорошая работа с большим личным архивом;
- уважение к приватности и self-hosted окружению.

## Продуктовая ставка

Главная ставка - не "еще один файловый клиент", а фотодоменная модель поверх Nextcloud:

- фото и видео как `MediaItem`, а не просто WebDAV-файлы;
- timeline, даты, EXIF, live photos, albums, favorites, tags, people/places как будущие доменные возможности;
- разные источники медиа за единым интерфейсом: Memories remote, Nextcloud remote fallback, Android local MediaStore.

## Принципы

- Сначала простая полезная вертикаль, потом синхронизация.
- Архитектура должна позволять добавлять источники медиа без переписывания UI.
- Серверная интеграция должна быть изолирована от доменной модели приложения.
- Bleeding edge допустим там, где он заметно упрощает код или UX, но каждое такое решение фиксируется в ADR.
- Документация сначала пишется для автора проекта. Если проект станет популярным, публичные документы можно будет перевести или продублировать на английском.

## Не цели на старте

- Полная замена Memories Web UI.
- Полная замена официального Nextcloud Android-клиента.
- Сложная двусторонняя синхронизация в первом MVP.
- Поддержка всех вариантов Nextcloud-конфигураций до появления первого рабочего tracer bullet.

## Открытые вопросы

- Насколько стабилен Memories API для стороннего native-клиента?
- Нужно ли проекту зависеть от установленного Memories app на сервере или нужен полноценный fallback на обычный Nextcloud?
- Какая лицензия будет выбрана для Android-клиента?
- Нужно ли проекту сразу ориентироваться на публикацию в F-Droid/Google Play?
