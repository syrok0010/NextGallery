# ADR 0016: Удаление выбранных медиа в корзины

## Статус

Принято.

## Контекст

У медиаобъекта может быть локальная копия, облачная или обе (`LocalFirst`). Удаление необратимо при неосторожном дизайне. Приложение не запрашивает права `MANAGE_MEDIA` или `MANAGE_EXTERNAL_STORAGE` (minSdk 31): чужие файлы MediaStore можно изменить только через системный диалог подтверждения Android.

## Критерии выбора

- Телефонные копии должны попадать в корзину, а для облачных до подтверждения нужно честно сообщать, активна ли корзина на сервере.
- Не требовать новых runtime-разрешений.
- Отказ пользователя от системного диалога телефона не должен оставлять удалённой облачную копию в том же действии.
- Не удалять чужой файл при перемещении на сервере между запросом пути и `DELETE`.

## Альтернативы

- **`createDeleteRequest` (удаление навсегда):** ошибочное удаление нельзя исправить.
- **Всегда удалять обе копии:** смешивает освобождение места на телефоне и удаление из облака.
- **Сначала облако, потом телефон:** отмена системного диалога оставила бы облачную копию уже удалённой.
- **Свой экран корзины в приложении:** отложено — восстановление есть в системной галерее Android и в вебе Nextcloud.
- **Кэшировать признак корзины на время сессии:** признак может устареть к моменту удаления; свежий запрос при открытии диалога проще и точнее.
- **Блокировать подтверждение до ответа сервера о корзине или удалять облако без ответа:** первое мешает удалить телефонные копии офлайн, второе рискует безвозвратно удалить облачные файлы без известного состояния корзины.
- **Проверять корзину через DAV `PROPFIND`:** capabilities даёт тот же факт одним JSON-запросом без DAV-пути и разбора XML (проверка стенда — в [api-nextcloud.md](../research/api-nextcloud.md)).
- **Разбивать выбор > 2000 URI на несколько системных диалогов:** нарушает правило «отмена не удаляет ничего».

## Решение

### Выбор области и проверка корзины Nextcloud

- Для объединённых объектов пользователь выбирает область («Везде», «Только с телефона», «Только из облака»); объекты с одной копией удаляются всегда.
- Если действие затрагивает облачные копии, при каждом открытии диалога запрашивается `GET ocs/v2.php/cloud/capabilities?format=json` (`NextcloudTrashBin`, не кэшируется). Облачные копии допускаются к удалению, только если сервер ответил к моменту подтверждения (`files.undelete: true` — в корзину, иначе — с предупреждением об удалении навсегда); при отсутствии ответа или ошибке удаляются только телефонные копии, а облако не трогается.
- Экран передаёт в модуль удаления только `MediaId` и область; физические URI и `fileId` фиксируются в `DeletionPreparation` из `MediaLibraryIndex` до системного диалога и не выходят за пределы модуля.

### Порядок, MediaStore и WebDAV

- Порядок всегда: сначала системный диалог корзины телефона (`MediaStore.createTrashRequest`), затем облако. Отмена системного диалога отменяет всё действие целиком.
- Локальный индекс читает `MediaStore.Files`, но `createTrashRequest` принимает только коллекции `images`/`video`/`audio`, поэтому `content://media/<volume>/file/<id>` переписывается в `.../images/media/<id>` или `.../video/media/<id>`.
- MediaProvider может вернуть `RESULT_OK`, даже если часть файлов не переместилась в корзину. После подтверждения каждая телефонная копия перечитывается с `QUERY_ARG_MATCH_TRASHED` и считается удалённой только при `IS_TRASHED = 1`.
- Android 16 отклоняет trash request больше чем на 2000 URI: такой выбор не разбивается и отклоняется целиком.
- Облачное удаление (`MemoriesCloudTrash`) получает путь и ETag через Memories `GET image/info/{fileId}` (в отличие от альбомов, где используется DAV `SEARCH`, ADR 0015), затем отправляет `DELETE remote.php/dav/files/{uid}/{path}` с `If-Match: "<etag>"` (до 4 одновременно). `2xx` и `404` считаются успехом, `412` и прочие ошибки — отказом конкретного файла.
- Облачная часть выполняется в application-scoped корутине (`MediaDeletionRepository`), публикует состояние через `OperationStatusSource` (ADR 0001) и блокирует выход до завершения (ADR 0006). После успешного удаления копии registry забывает её через `MediaIdentityRegistry.forget` (ADR 0002), затем вызывается `MediaLibraryCoordinator.refresh()`.

## Последствия

- После «Только с телефона» объединённый объект остаётся в ленте как облачный, после «Только из облака» — как локальный.
- Проверка `files.undelete` отражает состояние на момент открытия диалога, а не атомарную гарантию на момент каждого `DELETE`.
- Каждый облачный объект требует двух запросов (`image/info` и `DELETE`), поэтому удаление полагается на то, что объект уже проиндексирован Memories; телефонная копия требует повторного чтения MediaStore после подтверждения.
- DAV `DELETE` не подтверждает фактический способ хранения на сервере, поэтому облачный итог не обещает корзину.
