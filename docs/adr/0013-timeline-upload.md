# ADR 0013: Ручная загрузка из таймлайна

## Контекст

Пользователь должен отправлять локальные фото и видео в облако прямо из единого таймлайна. Отдельный picker разрывает связь с уже видимым медиаобъектом и не подходит для массового выбора. Memories API предоставляет timeline и `timeline_path`, но не endpoint для отправки файлов; для записи используется Nextcloud WebDAV.

## Решение

- Долгое нажатие на тайл включает режим выбора. В этом режиме обычный тап переключает выделение, а нижняя панель показывает количество выбранных объектов, отмену и действие загрузки.
- Выбор разрешён для любых медиаобъектов, включая уже облачные. В upload service передаются только локальные объекты без облачной копии: уже объединённый объект повторно не отправляется, а облачный объект без локальных байтов загрузить нельзя.
- Передача выполняется Android foreground service, запущенным явным действием пользователя. Сервис получает `timeline_path` из Memories config и отправляет каждый локальный URI потоковым WebDAV `PUT` в `remote.php/dav/files/{user}/{timeline_path}/{name}`.
- Для защиты от перезаписи сервис добавляет `If-None-Match: *`; ответ `412` считается уже существующим объектом.
- Прогресс живёт в системной notification foreground service. Персистентная очередь, resume после убийства процесса и связывание полученного Memories `fileId` с исходным `MediaId` остаются отдельными задачами.

## Критерии выбора

- Действие должно начинаться из текущего таймлайна и не требовать второго выбора файлов.
- Большие видео нельзя целиком читать в память процесса.
- Передача должна продолжаться при блокировке экрана.
- Нельзя молча перезаписывать существующий файл.

## Альтернативы

- **Обычный Activity/корутина:** не гарантирует продолжение передачи при уходе приложения в фон.
- **WorkManager:** лучше подходит для восстанавливаемой очереди, но не соответствует согласованному foreground-сценарию первой версии.
- **Memories upload endpoint:** в исследовании API такого endpoint не найдено; WebDAV является проверенным Nextcloud write-контрактом.

## Последствия

Пользователь получает единый сценарий выбора фото и видео и видит ход передачи в системной панели. Первая версия зависит от прав WebDAV и текущего `timeline_path`; при остановке процесса незавершённые элементы потребуется выбрать повторно. После индексации Memories может появиться новая облачная копия с другой эвристической идентичностью.

## Открытые вопросы

- Нужна ли персистентная очередь с retry/resume после перезапуска приложения?
- Как надёжно связать ответный remote `fileId` с локальным `MediaId`, минуя приблизительные AUID/BUID?
