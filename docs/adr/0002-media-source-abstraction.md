# ADR 0002: Граница источников и identity медиа

## Статус

Пересмотрено после реализации unified timeline.

## Контекст

NextGallery объединяет Memories metadata и Android MediaStore в один timeline. Общий интерфейс `MediaSource`, задуманный до реализации, оказался слабым seam: источники имеют разный lifecycle, pagination и persistence. Общей должна быть опубликованная доменная модель, а не форма чтения источника.

## Критерии выбора

- Memories DTO и MediaStore rows не попадают в UI.
- Каждый source сохраняет собственный ingestion и lifecycle.
- Объединение источников выполняется в одном месте.
- UI identity не зависит от Memories `fileId` или MediaStore URI.
- Ошибочная эвристика не должна необратимо объединять разные медиа.

## Альтернативы

### Общий `MediaSource`

Упрощает список источников, но вынуждает скрывать несовместимые модели загрузки за широким или условным интерфейсом.

### UI объединяет source-specific списки

Сохраняет adapters простыми, но размазывает дедупликацию, metadata priority и identity по UI.

## Решение

- `MemoriesRepository` и `LocalMediaSource` самостоятельно читают, идентифицируют и сохраняют свои проекции.
- `UnifiedTimelineProjection` объединяет уже идентифицированные local/remote элементы в памяти и не обращается к Room.
- UI получает `MediaItem` с устойчивым `MediaId` и `MediaAssetRef`, описывающим доступные bytes.
- Memories metadata задают каноническое имя, дату и положение объединённого объекта.
- Локальная копия предпочтительна для thumbnail/original; ошибка local URI переключает загрузку на cloud copy без смены `MediaId`.

## Identity

Точные source identifiers сохраняются в Room как отображение на `MediaId`, а приблизительные aliases — как наблюдения конкретной source copy:

- local source: MediaStore URI;
- remote source: Memories `fileId`;
- `AUID = MD5(epoch + size)`;
- `BUID = MD5(basename + "iuid=" + ImageUniqueID)`;
- fallback BUID: `MD5(basename + "size=" + size)`.

AUID/BUID — текущие наблюдения, а не история: повторная индексация source copy заменяет её набор aliases, включая переход к пустому набору. Устаревшие наблюдения всей входящей партии удаляются до approximate matching в той же транзакции. Alias другой copy того же `MediaId` остаётся активным, пока эта copy его наблюдает; удаление источника очищает только его наблюдения. Конфликтующие новые aliases, как и прежде, не публикуются для сопоставления. Неизменившаяся индексация идемпотентна. Хранение aliases только на уровне `MediaId` отвергнуто: оно не позволяет отличить устаревший alias одной copy от актуального alias другой (#124).

Совпадение AUID или BUID объединяет копии, только если найденные aliases ведут к одному `MediaId`. При конфликте копия остаётся отдельной, а конфликт сохраняется для диагностики. При появлении remote copy уже опубликованный local `MediaId` сохраняется.

Подтверждённое исчезновение copy при полном MediaStore scan, полной замене облачного дня или исчезновении дня из полного индекса очищает только её aliases, сохраняя exact identities, явные связи ADR 0017 и наблюдения других copies. Частичные ответы, ошибки и инвалидация кэша по изменению счётчика дня не подтверждают исчезновение: прежняя cloud metadata сохраняется скрытой до полного пересчёта дня (#146).

Сохранённый source identifier имеет приоритет над alias. Поэтому точная связь, полученная через `OC-FileId` или уже записанную пару source identity, не может быть переопределена устаревшим или коллидирующим AUID/BUID. При расхождении source identity и alias сохраняются отдельный объект и конфликт.

## Последствия

- Источник можно менять без переписывания UI, пока он публикует доменные элементы.
- Identity восстанавливается до публикации элемента; session-only IDs не используются.
- Эвристика AUID/BUID остаётся приблизительной и используется для первичного сопоставления копий, появившихся независимо. Явная sync-связь всегда сильнее и сохраняется при повторной индексации.
- Source ingestion сложнее общего интерфейса, но его различия остаются локальными.
- Замена aliases не разделяет уже связанные копии и не меняет точные source identifiers или явные связи ADR 0017, включая связывание после `412`. Для схемы Room 11 используется допустимый в разработке destructive reset: прежние aliases нельзя надёжно приписать copy, а миграция локального dev-состояния не требуется.
