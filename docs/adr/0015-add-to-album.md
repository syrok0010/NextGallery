# ADR 0015: Добавление выбранных медиа в альбом

## Статус

Принято.

## Контекст

Альбомы Memories — это альбомы Nextcloud Photos. Каталог и содержимое читаются через Memories API, но write-endpoint у Memories нет: добавление фото и создание альбомов выполняются через Nextcloud DAV.

## Критерии выбора

- Использовать проверенный контракт Nextcloud Photos DAV, а не недокументированные write-эндпоинты.
- Не загружать локальные файлы неявно без подтверждения пользователя.
- Не зависеть от задержки индексации Memories для свежезагруженных файлов.
- Не добавлять в альбом файл, который может оказаться другим фото с тем же именем.
- Не показывать альбомы, запись в которые заведомо завершится ошибкой прав.

## Альтернативы

- **Пропускать локальные объекты:** пользователь не видит в таймлайне, у какого фото есть облачная копия, поэтому действие часто ничего бы не делало.
- **Искать путь файла через Memories `image/info/{fileId}` (с повторами до индексации):** до индексации Memories отвечает `404`, который неотличим от недоступного файла, а время индексации непредсказуемо (#110). DAV `SEARCH` читает файловый кэш Nextcloud сразу после загрузки.
- **Добавлять загруженные файлы по `fileId` после индексации Memories:** `COPY` по известному DAV-пути из загрузки не требует ждать индексации.
- **Создавать новый альбом внутри модуля загрузки:** `MKCOL` из `AlbumAdditions` и загрузки конкурировали бы, порождая ложный `405` («альбом уже существует»).
- **WorkManager для уже облачных копий:** избыточен — запросы `SEARCH`/`COPY` короткие и не передают содержимое файлов (чисто локальные объекты идут через WorkManager по ADR 0019).
- **Shared-альбомы (`photos/{uid}/sharedalbums/...`):** права коллабораторов на запись не проверены, поэтому запись ограничена собственными альбомами.

## Решение

### Протокол DAV для облачных и объединённых объектов

- Запись выполняется через Nextcloud DAV с `uid` из `AccountCredentials.userId` (ADR 0006), а не login name:
  - поиск пути файла — `SEARCH remote.php/dav/` в области `/files/{uid}` по `oc:fileid = {fileId}`;
  - добавление в альбом — `COPY remote.php/dav/files/{uid}/{path}` → `remote.php/dav/photos/{uid}/albums/{album}/{name}`;
  - создание нового альбома — `MKCOL remote.php/dav/photos/{uid}/albums/{album}`.
- `409 Conflict` на `COPY` Photos возвращает и для уже присутствующего файла, и для отсутствующего альбома. При `409` альбом проверяется одним `PROPFIND`: если существует — успех, иначе (или при сбое проверки) — ошибка этого файла. `405` на `MKCOL` означает существующий альбом.
- В список доступных для записи попадают только альбомы, где владелец из `cluster_id` (`owner/name`) совпадает с `uid`.
- Прямая операция для облачных копий выполняется в application-scoped корутине (`AlbumAdditions`, по одной операции одновременно, до 4 `COPY` параллельно), публикует состояние через `OperationStatusSource` (ADR 0001) и блокирует выход до завершения (ADR 0006).

### Локальные объекты

- Чисто локальные объекты передаются в персистентную очередь загрузки с выбранным `UploadAlbum` (ADR 0014, ADR 0019); `COPY` по загруженному DAV-пути выполняет шаг `AlbumUploadFollowUp` модуля альбомов без ожидания индексации Memories.
- Модуль загрузки не создаёт альбомы: задания ставятся в очередь только после того, как `AlbumAdditions` получил адрес альбома (для нового — после успешного `MKCOL`), иначе `COPY` мог бы опередить создание альбома. Если альбом создать не удалось, загрузка не запускается.
- Файл, давший конфликт имени при загрузке, до шага добавления в альбом не доходит.

## Последствия

- Добавление работает для облачных, объединённых и чисто локальных объектов в собственные альбомы.
- Объект, добавляемый по `fileId`, требует двух запросов (`SEARCH` + `COPY`); шаг после загрузки делает только `COPY` по известному пути. Для сотен объектов это медленнее пакетного API, но пакетного API нет.
- Счётчики в каталоге альбомов зависят от индексации Memories: свежедобавленный файл может появиться в каталоге позже.
- Загрузка и шаг добавления локальных объектов переживают смерть процесса (ADR 0019); прямая операция для уже облачных копий живёт в памяти процесса.

## Открытые вопросы

- Запись в shared-альбомы и проверка прав коллаборатора до показа альбома.
- Действия с экрана открытого альбома и его viewer (#133).
