# ADR 0018: Русский язык приложения

## Статус и контекст

Принято по решению автора в [#103](https://github.com/syrok0010/NextGallery/issues/103).
Русские строки уже находятся в `values/`, но это не задаёт язык конфигурации:
при системном английском Android выбирает «2 элементов», а даты — «31 October».
Приложение поддерживает Android 12+ (API 31), использует Compose и `ComponentActivity`.

## Критерии и решение

Нужны одинаковые русские plurals и даты в UI и уведомлениях на всех поддерживаемых
версиях, сохранение системного выбора пользователя и минимальное изменение стека.

Объявляем единственный поддерживаемый язык `ru` в `localeConfig`. На Android 13+
при первом запуске после установки/обновления задаём `LocaleManager.applicationLocales = ru`,
если явного выбора ещё нет. Отдельный маркер инициализации не позволяет повторно
заменять выбранный позднее пункт «Язык системы»; существующий `ru-RU` сохраняется.
На Android 12/12L системного per-app API нет: используется только fallback ресурсов.

Если ведущий язык конфигурации не русский, ресурсы Application и MainActivity
получают русский fallback. Это нужно и на Android 13+, когда пользователь выбрал
«Язык системы» на английском устройстве: список поддерживаемых языков сам по себе
не меняет правила plurals. Fallback не записывает системный выбор. Application
повторно применяет его при изменении конфигурации; уведомления разрешают `UiText`
через Application context. Даты используют locale конфигурации Compose с ключом
`remember`, чтобы форматтер обновлялся вместе с UI. Глобальную JVM locale вручную не меняем.

## Альтернативы

- `AppCompatDelegate.setApplicationLocales`: для Compose на Android 12 требует
  `AppCompatActivity` и интеграции AppCompat. Смена Activity/темы и добавление
  зависимости ради одного языка расширяет риск; fallback для «Языка системы»
  всё равно нужен.
- Только `localeConfig` и однократный `LocaleManager`: не покрывает API 31–32
  и возврат к системному английскому.
- Явная русская locale в каждом вызове plurals/дат: легко пропустить Compose,
  новый экран или уведомление; сохраняется расхождение ресурсов и конфигурации.
- Английские `values/` и русские `values-ru/`: требует полного перевода,
  вынесенного в [#148](https://github.com/syrok0010/NextGallery/issues/148).

## Последствия и открытые вопросы

В системном меню доступны русский и «Язык системы»; английский перевод отсутствует,
поэтому оба варианта пока дают русский интерфейс. `ru-RU` через `cmd locale` остаётся
допустимым вариантом русского. Строки в `values/` сохраняются.

При добавлении второго языка нужно расширить `localeConfig` и политику fallback,
определить поведение «Языка системы» и миграцию уже установленного русского выбора.
Новые Android entry points, использующие собственные ресурсы, должны учитывать
fallback, как MainActivity; тексты уведомлений используют Application context.

Источники: [языки приложения](https://developer.android.com/guide/topics/resources/app-languages),
[LocaleManager](https://developer.android.com/reference/android/app/LocaleManager).
